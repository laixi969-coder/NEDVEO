# 现有同类产品、竞争定位与全球信源策略（2026-11-08 初版）

> 本文件是**公开网络研究基线**，不是已验证的市场份额或完整竞品数据库。每次正式商业决策前须重新核对产品是否仍运营、功能、定价、许可和数据时效。
> 研究目标：区分「趋势发现」「痛点挖掘」「竞品数据」「创意生成」「真实验证」等不同工作，而不是把它们错误地当作同一种竞争对手。

## 一、产品级竞品 / 替代工具

| 参考工具 | 可从官方公开页面确认的定位/能力 | 我们可学习的部分 | 目前未证明的部分/可能缺口 |
|---|---|---|---|
| Exploding Topics | 多源趋势搜集、分类、趋势指标、趋势关联及预测；产品/创业公司趋势数据 | 全球趋势 radar、跨主题聚类、长期趋势 | 不能仅据其趋势数据判断真实付款、个体适配或执行闭环；具体订阅权限需另核 |
| Product Hunt | 新品发布、点赞评论、面向早期采用者的反馈与曝光 | 新品/竞品发现、早期评论分析 | 点赞不是成交；也不是全行业需求数据库 |
| Similarweb | 竞争网站流量、参与度、搜索、营销渠道的比较研究 | 竞品数字足迹、市场份额代理指标、地理分布 | 网络流量不等于营收，实体/私域企业覆盖有限；具体访问许可待核 |
| Google Trends | 搜索兴趣趋势，可导出 CSV、分享图表 | 时序异常、地区关键词兴趣、季节性 | 相对搜索兴趣不等于购买意愿；不得将搜索指数理解为销量 |
| Trends.vc | 新市场/创业想法研究报告与创始人社区 | 人工研究模板、行业进入视角 | 样本覆盖及是否提供连续证据回放未在本轮验证 |
| Startup Ideas AI | 按分类展示创业产品构想/灵感 | 内容发现与轻量筛选体验 | 仅由页面看不出是否有可审计证据或付款验证机制 |
| GummySearch（历史对标，不可视为可接入竞品） | 曾提供 Reddit 受众/痛点研究；其创始人披露因未能取得可行的 Reddit 商业许可安排，2025-11-30 起停止新业务 | **数据授权是一等产品风险**：要能随时停用一个来源而不使全系统崩溃 | 不得将其作为 2026 年可正常注册的可用服务 |

## 二、差异化定位：我们究竟多做什么

**定位：不是「预测下一个热点」，而是「指出一个特定主体是否应该投入资源，以及接下来应验证哪项假设」。**

| 用户工作 | 趋势工具 | 竞品/数据工具 | 创意生成工具 | 本产品目标（规划，不代表已实现） |
|---|---|---|---|---|
| 发现增长信号 | 强 | 部分 | 弱 | 全球多源/按行业与人群限定 |
| 把抱怨转为具体场景的需求 | 部分 | 部分 | 常靠猜测 | 场景、受益者、替代方案、需求证据 |
| 价值—共识—模式分析 | 通常非核心 | 通常非核心 | 可能凭模型推理 | 结构化三层分析＋关键反证 |
| 证据可信度与错误风险 | 不一 | 数据方法各异 | 不一 | 可追溯、证据冲突、版本回放 |
| 无付费数据继续研究 | 部分 | 数据缺失时较弱 | 容易幻想 | 代理证据、付费等级、最低成本实验 |
| 角色适配（创始人/企业/投资人） | 偏通用 | 各有偏重 | 泛化 | 同证据三种决策视角 |
| 从机会走向 MVP/真实实验 | 通常不完整 | 非主战场 | 可能输出草案 | 有阶段性行动与结果回填的孵化工作台 |
| 跨市场迁移与长期回溯 | 各有能力 | 各有能力 | 通常弱 | 来源地区、目标地区、文化/监管/渠道差异 |

这是一张**功能目标差异表**，不是经全面竞品实测后的绝对优劣排名；公开网页可能只展示免费/营销部分。

## 三、信源准入矩阵（不应默认已经获得 API/抓取权）

| 类型 | 示例 | 主要信号 | 合法接入备选 | 风险/验证 |
|---|---|---|---|---|
| 新品/开发生态 | GitHub 公共项目、Product Hunt | Issue、需求请求、评论、早期竞品 | 官方 API / 公开许可 / 手动导入 | 审核 API 商用、rate limit、转载许可 |
| 搜索趋势 | Google Trends / 地区搜索报告 | 意向变化、需求关键词 | 官方功能、授权导出、合法数据供应商 | 只有兴趣代理数据，不能写成交 |
| 社区/问答 | Reddit、Hacker News、知乎、Stack Exchange | 抱怨、求助、替代办法 | 官方 API/许可、授权导出、手动提交 | 用户隐私、条款和数据使用权差异大 |
| 社交/内容 | 小红书、抖音、YouTube、X | 场景语言、痛点与情绪 | 官方可用接口、品牌授权、合法第三方 | 强调反营销内容/重复转载识别 |
| 电商/应用商店 | 公开评论、App Store / Google Play | 竞品不足、具体购买/退货描述 | 合法数据接口、商家/用户授权上传 | 评论不是付款收据；规则不同 |
| 企业与创投 | 企业官网、招聘、投融资公开记录 | 新进入者、融资、岗位投入 | 官方开放数据、付费授权库 | 宣传口径 ≠ 营收/增速事实 |
| 政策/招标/专利 | 政府公开数据、招标公告、专利检索 | 预算、合规、技术路线 | 主管部门开放数据/许可公开库 | 地区适配；中标≠实际付款 |
| 私有客户资料 | 用户访谈、投诉、CRM 导出 | 高价值一手证据 | 用户上传与企业授权集成 | 默认私有；撤销、删除、脱敏 |

推荐最初 3 类可执行连接器：①已核实许可的开放 RSS/官方 API；②用户授权文件上传；③本地演示测试数据（显著标记模拟）。不依赖任何可能违反服务条款的平台爬虫作为 MVP 的核心链路。

## 四、信源准入状态机

```text
CANDIDATE -> RIGHTS_REVIEW -> APPROVED -> ACTIVE
                                  |        |
                                  v        v
                               DENIED   PAUSED / REVOKED
                                           |
                                           v
                                   PURGE_OR_RETAIN_PER_POLICY
```

注册来源必须有：`platform`, `access_method`, `terms_url`, `permitted_purpose`, `license_status`, `commercial_use_allowed`, `personal_data_policy`, `retention_days`, `rate_limit`, `owner`, `last_checked`, `revocation_action`。

系统不应默认「通过公共网页可以浏览」等于「允许自动化批量存储、再分发、商业使用」。

## 五、每个机会的竞品分析标准

1. 不局限于列品牌：收录**直接竞品、间接竞品、人工流程/Excel/服务商替代方案、完全不消费**。
2. 记录：官网、地域、客户、切入场景、功能、定价页、定价生效日、用户抱怨、差异化、证据、最后核对时间。
3. 将竞品事实与推断分开：`pricing_public`、`revenue_confirmed`、`traffic_estimated`、`funding_reported` 分属不同字段。
4. 结果必须回答：「为什么不是现有方案就够了？」和「我们的哪个进入路径有证据？」
5. 每日更新不强制重新深研所有竞品；发生新价格、重大功能或评论变化时对关联机会做增量复核。
6. 对未知竞品数量、未知市场份额允许 `UNKNOWN`，不能自造“已扫描全部竞品”。

## 六、待调研清单（不能在 PRD 中当作已验证事实）

- 各平台商业 API/批量访问许可、费率、访问地域限制：尚未逐项取得合同，**不可直接接入**。
- 不同信源对同一需求的独立性：须测转载与机器人话题污染。
- 平台级竞品的真实用户数、收入、企业合同价、留存：本轮未核实，不做结论。
- 信源覆盖率：须用实际采样与人工召回率标注，不用“全球全网覆盖”广告语。
- 开发预算：待 B1 实测单位采集/单位高质量报告的真实花费后参数化填入。

## 七、当源不可用时的降级策略

- 用户指定来源不可用：解释许可/访问原因、已覆盖的替代来源和导致的证据缺口；绝不跳过并伪称已检索。
- 单一市场无付费资料：启用替代成本与付款人映射，标记未知，推荐最低成本实验。
- 竞争者失联/失效：保留历史快照，标注最后确认日期，不把已倒闭者当在售产品。
- 大量源重复：来源簇去重后再计样本，不将 10 次转载算 10 个独立需求者。
