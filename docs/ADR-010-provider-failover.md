# ADR-010：国内／海外双模型服务与受控故障切换

日期：2026-11-09。状态：已实现。

## 配置与兼容

本机或工作空间原有的 AES-GCM 加密 vault 文件继续使用。读取旧单服务配置时，逻辑映射为 `domestic` 槽位；只有用户保存／删除配置或切换规则时才写入版本2封装。两个槽位独立保存 API 地址、密钥、协议、模型、费率、输出额度和预算。公共响应使用字段白名单，不回显密钥或整个 vault。

国内／海外是配置标签，不检测服务器地理位置，也不按研究市场硬切换。设置页可选择默认服务，研究可指定本次服务；未指定时在建任务时固定当前默认服务。每日跟踪保留指定服务。改变地址不会把另一个地址或另一个槽位的已保存密钥转发过去；删除一套保留另一套，必要时将剩余服务设为默认。

两套不同配置齐备后，默认开启的自动切换规则才具备执行条件。只有一套配置时继续使用单服务。模型同步与测试针对当前槽位；响应测试及指定不同模型的反向论证不会隐式切换。

## 切换规则

| 情况 | 行为 |
|---|---|
| 可识别网络连接错误，如 ECONNRESET、ECONNREFUSED、ENOTFOUND | 若允许自动切换，尝试备用一次 |
| 明确的限流码，例如 rate_limit_exceeded、Throttling.RateQuota | 可切换，保留供应商 Retry-After 冷却期 |
| HTTP 500、502、503、504、529 暂时不可用 | 可切换；有 Retry-After 时遵守等待期 |
| 超时／HTTP 408 | 默认直接报错；单独开启超时切换才尝试备用，原请求费用仍可能未知 |
| 401、403、404、400、余额／账单额度不足、含义不明的429 | 直接报错，不隐式更换服务 |
| JSON、模型输出、schema、引用校验错误 | 直接报错，不为修复质量问题自动重复付费 |
| 用户取消、预算不足 | 不切换 |
| 私人材料未勾选本次备用授权 | 不将私人材料发送至备用服务，明确说明阻断原因 |

同一次逻辑调用最多两次供应商请求。同一任务切换成功后后续阶段继续使用备用，不来回尝试；新任务重新优先默认服务，仍尊重供应商冷却期。用户手动重试清除任务内的备用粘滞状态；修改模型配置也使旧粘滞状态失效。

错误分类依据状态码及可识别错误字段，不记录供应商任意原始错误正文。OpenAI 的429可能区分速率与额度，不能仅凭HTTP状态切换；参考[官方错误文档](https://developers.openai.com/api/docs/guides/error-codes)。兼容服务分类参考[Model Studio错误文档](https://www.alibabacloud.com/help/en/model-studio/error-code)。

## 费用、记录与边界

每个实际请求单独写入账本，记录槽位、地址、模型、阶段、尝试序号、调用组、实际usage和费率。失败且费用无法确认时保留保守预留或未知金额，不填写虚假的零费用。备用阶段按其自身输出额度限制，费用检查同时遵守本次首选及备用配置中的较低金额上限。预算范围内出现费用未知的调用时不能利用切换绕过预算。

研究任务、报告快照及Markdown／文档导出保留实际调用和切换记录。核心研究与商业分析可能由不同服务完成，分别记录。旧研究快照不回写。新报告的追问、孵化草稿和结构化评估优先沿用核心研究实际服务，避免因后来修改默认服务而静默更换材料接收方。私人项目草稿和包含用户画像的生成请求默认不跨服务自动发送；公开报告追问可以使用主备，含私人证据的追问默认阻止切换。显式反向论证固定用户指定模型。

切换模型仅处理模型接口故障，不能修复信源网站的网络连接或访问策略。

## 验证

隔离测试覆盖旧配置兼容、密钥白名单、独立槽位、主服务故障后的完整核心／商业研究流程、一次切换与任务内继续备用、冷却、取消、超时开关、余额和未知429不切换、私人材料授权、预算不能绕过、费率与账本、报告导出。界面测试覆盖两套密钥草稿隔离、模型同步／响应测试、独立保存、默认服务及超时规则和手机布局。

两家真实供应商的现场切换需要操作者配置第二套有效服务；固定测试响应不能替代该项实网验收。现有 qwen3.8-flash 已在新代码下通过真实最小JSON请求，记录输入37／输出5 tokens，未填费率所以费用未知；尚未配置真实备用服务。现有单服务配置继续可用，不创建供应商账号，不代填或猜测凭据。
