> 品牌：中文＋英文双品牌，**尚未定名**，不得将工作名直接用作商标或域名。\

## 0. 执行摘要与产品边界

**一句话定位**：持续从全球合规信源发现真实问题与潜在市场，按「价值—共识—模式」验证其是否是好需求、好产品、好生意，给出可追溯的证据、竞品与市场进入判断，并将值得研究的机会持续推进到真实验证与产品孵化。

**北极星指标（暂定）**：30 日内，至少一位实际用户依据系统的**可溯源研究**完成一项可核查的商机决策动作（完成访谈、启动付费意向验证、立项/否决等）；以决策质量的人工审查作为护栏，不允许单纯通过生成报告提升指标。封闭内测前再与试点人员共同设定绝对目标值。

核心价值承诺：
1. 不是创意生成器，而是**证据驱动的机会研究与决策系统**。
2. 不是仅统计热度，而是同时检查**需求强度、付费/受益关系、成交共识、变现模式、进入窗口和执行能力**。
3. 不是无证据就停机：缺少付费数据时可做**代理证据推断与低成本验证建议**；同时严禁把推断写成「已确认付费」。
4. 不是每天硬凑榜单：质量门槛不达标，可以是 0 条推荐；低证据机会单列「待验证/未来观察」。
5. 不是一份静态报告：机会、证据、竞品、结论和研究版本持续演化。

### 0.1 服务对象及主要任务

| 人群 | 核心决策 | 重要输出 | 典型成功动作 |
|---|---|---|---|
| 个体创业者/独立开发者 | 我能否用现有资源切入并赚钱？ | 差异化切入口、MVP、资源要求、验证方案 | 做访谈、设计预售、启动 MVP |
| 企业产品/创新团队 | 是否值得占用预算、人力、战略资源？ | 市场缺口、利益相关人、组织匹配、能力系统 | 内部立项、执行试点、否决项目 |
| 投资人/孵化器 | 是阶段性热度还是有规模、结构优势的机会？ | 市场结构、增长信号、交易机制、团队/风险假设 | 建立观察清单、尽调、投决前否决 |

用户首次选择角色仅设定默认工作台/权重，不改变证据原文和基本事实。可随时切换角色比较结论。

### 0.2 产品形态与发布路径

- 长期：响应式 Web 研究工作台＋自然语言 AI 助手＋独立移动端＋管理控制台。
- 第一阶段：**响应式 Web + 内置对话助手 + PWA/移动浏览器访问**，原生 App 留到后续。
- 本地开发、云端运行、基础设施可迁移；采用模块化单体优先，预留分布式迁移接口。
- 本人使用→邀请制封闭内测→达到门槛后公开注册；**暂不确定收费方案与固定交付日期**。

### 0.3 本期不做 / 不保证

- 不承诺接入全部全球平台、绕过反爬或付费墙、未经授权收集社群私有数据。
- 不承诺预测创业成功率，不把 AI 共识当实证，不把评分当投资意见。
- 不自动替用户付款、投广告、私信用户或对外公开研究；需要明确细粒度授权与操作记录。
- V0 不自建通用搜索引擎、不研发大模型、不做全功能 Jira/CRM、不制作原生移动 App。
- 用户私有研究资料不得进入公共推荐，也不得默认用于模型训练。

## 1. 业务方法论：原书框架的产品化

本平台以《真需求》中的「价值—共识—模式」商业闭环为主框架，而不是简化成「痛点数 × 讨论热度」。

| 原书维度 | 原书内的核心议题 | 产品中的可操作检查 |
|---|---|---|
| 价值（Value） | 功能价值、情绪价值、资产价值；需求由买方决定；产品价值组合 | 谁在什么场景有何损失/渴望？实际购买何种功能、保障、愉悦、彰显或资产预期？有哪些可观察行为？ |
| 共识（Consensus） | KANO 五类属性、用户人设、产品场景匹配、利益相关人、认知/关系 | 用户是否感知到价值？有哪些认知、场景与利益阻力？谁购买、谁使用、谁影响、谁批准？成交为何没有发生？ |
| 模式（Model） | 能力系统、变现逻辑、分配机制；模式第一问「拿谁的钱」 | 钱来自谁（C/B/VC/G/其他）？成交、交付、获客、回款、复购/续费是否可持续？团队能否积累而非耗尽竞争优势？ |
| 求真（Truth seeking） | 应然与实然、行动证据、第一性原理 | 区分想象与现实，主动找反证，问品类底层目的是什么，记录未验证假设与退出条件 |

**重要界限**：书中是经营/产品方法论，并没有直接给出本平台的「0–100 商机评分公式」。下面的打分、证据等级和自动化规则是我们的**产品工程设计**，必须标记为 `scoring_version`，通过历史案例回测，不得冒称为梁宁原书公式。

## 2. 核心业务对象及定义

- **原始信号 Signal**：一个可回溯到来源的最小观察，例如投诉、价格变更、职位招聘、购买/放弃行为、论坛问题、政策和技术变化。
- **证据 Evidence**：被抽取、去重、许可检查、校验后，可支撑或反驳某项主张的材料；不等于事实已经成立。
- **需求 Need**：`目标用户 × 具体场景 × 待完成任务/情绪诉求 × 当前阻碍/代价`；需求与用户提议的方案必须分离。
- **市场机会 Opportunity**：在限定地区、客群、场景、时间窗口中，能以某种价值组合和商业模式解决需求的候选方案。
- **竞争者 Competitor**：直接同类、间接品类、替代方式（人工、Excel、不消费、已有流程）均需覆盖。
- **关键假设 Hypothesis**：足以使机会评级显著变化但尚未证实的命题。
- **研究案例 ResearchCase**：针对机会的版本化证据、推论、风险、角色观点和下一步建议。
- **孵化项目 VentureProject**：用户主动将机会转为项目后管理验证实验、PRD、MVP、里程碑和结果的私有工作空间。
- **市场 Market**：地区/语言/文化/法规/支付习惯组合；同一需求跨市场需另建机会视角，不共享本地结论。

## 3. 一级信息架构

导航：`今日机会` / `机会数据库` / `趋势雷达` / `自定义挖掘` / `竞品情报` / `孵化工作台` / `关注与预警` / `我的研究` / `账户与配置`。

后台：`运行总览` / `信源与采集许可` / `模型与费用` / `Skill/评估版本` / `任务与重试` / `证据质检` / `用户/租户/权限` / `通知` / `审计日志` / `事故与告警`。

### 3.1 今日机会：首页卡片最少字段
`标题、主要国家/地区、明确目标人群、场景、需求摘要、为什么现在、价值/共识/模式三维摘要、商业潜力等级、证据可信度、需求成熟度、进入难度、适配度、付费证据阶段、关键反证、前三竞品/替代方案、最后研究时间、查看来源`。

等级绝不只用颜色表达。凡低可信结果，即使潜力高，也显著标注「假设待验证」。

### 3.2 机会详情（默认固定章节）
1. 核心结论（已知/推断/未知 + 更新时间）；2. 人群-场景-任务；3. 价值构成；4. 用户行动证据时间线；5. 付费链路（使用者/受益者/预算人/支付者/批准者）；6. 竞品与替代方式；7. 共识摩擦；8. 变现与单位经济模型；9. 竞争/差异化与进入窗口；10. 反证与否决条件；11. 可执行最小实验；12. 角色适配结论；13. 研究版本与源证据。

## 4. 功能需求（FR，具备明确验收口径）

### FR-01 信源注册、许可及健康管理（P0）
- 管理员配置 source_id、类型、国家、语言、API/RSS/用户上传方式、授权依据、条款版本、允许的用途、频率、有效期、PII 风险、成本、健康状态。
- 每个 connector 返回统一 `SignalEnvelope`；失败不阻塞全局；支持停用、凭据轮换、增量 cursor、重试、审计。
- 若商业用途授权不明确，状态设 `pending_legal_review`，生产采集禁用；授权到期自动停用并通知管理员。
- 只抓取允许存储的内容；不许可保存正文时仅存 permitted 摘要/元数据和源链接，允许清除与过期处理。
- **验收**：在 1 个许可 RSS、1 个公开 API、1 个用户上传样本上完成增量采集；一个 source 故障不会阻塞其他来源。

### FR-02 自动发现与定向挖掘（P0）
- 每日按用户时区编排全局扫描；支持自定义关键词/行业/人群/场景/国家/预算/竞品 URL/模糊想法，且可保存为周期任务。
- 自由输入先经解析器分成 `问题/需求/拟议方案/商业假设/筛选条件`，不自动认同用户主张。
- 跨语言归一与原文并存；多义词和语境置信不足时降置信并进人工核查队列。
- 先低成本候选抽取，再按新颖度/重要性进入深度研究队列。
- **验收**：相同请求重试幂等；能按国家和角色复用同一个问题提出不同的后续研究任务。

### FR-03 证据治理与可信度引擎（P0）
- 记录原始链接、采集时间、原始发布时间、采集许可、内容摘要/加密副本、语言、规范 URL、来源类别、claim、支持/反对/中性、强弱、完整性和采样偏差。
- 去重至少三层：规范链接精确去重、内容指纹近重复、跨站转载/同源引用聚合；同一营销活动的 50 篇转载不得计为 50 份独立证据。
- 交叉验证必须基于**独立证据簇**；提供来源冲突摘要、缺口和人审入口；可报告 `insufficient_evidence`。
- 负面证据优先检索（替代方案免费足够、用户购买意愿弱、监管限制、竞品已解决等）。
- **验收**：同一文章 20 次转载合并成 1 个证据簇；模型不得引用不存在的 URL；删除源数据后引用正确失效。

### FR-04 需求知识图谱与去重（P0 数据关系；P2 高级可视化）
- 以 `Need / Persona / Scenario / Evidence / Opportunity / Competitor / Market / Hypothesis` 以及 `supports, refutes, substitutes, targets, emerges_from, applies_to` 等类型化关系连接。
- 合并有审计：记录 `merged_from`、阈值、人工批准，允许拆分回滚；跨市场同一根需求但当地结论独立。
- 同一需求的新证据更新 `updated_at` 和下一轮研究，不创建重复的「今日新机会」。
- **验收**：同义表达可归类、不同人群场景可拆分、误合并可恢复，旧引用可跳转到最新实体。

### FR-05 原书驱动「价值—共识—模式」分析（P0）
- 价值：按功能/情绪/资产三维分析，指明实际诉求与可验证的交付结果；情绪价值具体识别保障/愉悦/彰显与心理账户，不默认高热度=价值。
- 共识：KANO 五类属性按目标用户证据估计；列用户人设与场景、利益相关人及认知/交易阻力。
- 模式：识别付款主体、交易流程、商业单位经济、能力系统与分配激励，检查组织持续经营的可行性。
- 求真：列支持、反对、未知，指出每个核心论断应由什么实验验证。
- **验收**：每一个结论节点有 `claim_id`、来源引用、模型版本和反证；不能引用的结论一律标成假设。

### FR-06 缺少付费数据的推断与验证（P0；新增刚性要求）
- 必须明确区分 `使用者`、`受益者`、`支付者`、`预算人`、`购买决策人`、`合作方`；多人群平台同样适用。
- 付费证据 0-5 阶见 02 号文档；缺乏收入数据时，从替代方案支出、人工工时、现有项目预算、公开采购合同、询价行为、门槛动作等合规代理变量建立**假设范围**。
- 限制：花费时间 ≠ 必然愿意付费；竞品收入 ≠ 本产品可得收入；参与讨论 ≠ 购买承诺；询价 ≠ 成交；低成本 / 免费替代工具可能压低价格上限。
- **绝不因缺少直接付费证据而自动淘汰**。输出 `商业潜力预测`、`付费证据等级`、`未验证假设` 和 `下一项最低成本验证行动` 四者独立字段。
- **验收**：输入高痛点、无直接付款证据的案例，仍可进入 `需实验验证` 队列；系统不得输出「付费意愿已证实」。

### FR-07 竞争情报（P0 基础；P1 动态深度）
- 扫描直接竞品、间接竞品、替代方案、不消费的后果；包含官网/产品页、功能、定价（含币种/税/地区/套餐/时间戳）、细分客群、评价、优势、痛点、市场覆盖。
- 收入、融资、市场份额：仅在合法且可核验时给具体值，明确日期/口径/来源；否则标 `unknown` 或带假设的区间估算。
- 同一产品跨境、跨版本需区分；竞品变化纳入变更事件、与相关 Opportunity 重评关联。
- **验收**：至少给出 3 种竞争角色（直、间、替代）或明说检索覆盖不足；更新前后展示差异和数据时间。

### FR-08 多维评级与角色适配（P0）
- 独立输出：`需求真实性`、`产品机会`、`商业可行性`、`市场进入价值`、`落地难度`、`用户适配`、`证据可信度`、`需求成熟度`。
- 价值/共识/模式各自有透明分维度。高潜力但低可信不等于 S 级「推荐立即投入」。可标 `S潜力/低可信/仅限验证`。
- 保留评分版本、特征、权重、标准化方式、模型输入摘要、人工修订、评分差异；不对每个机会强行给数字。
- **验收**：修改角色后仅适配/角色权重变化，基础证据保持不变；关键反证触发重评，历史可回溯。

### FR-09 双轨机会库、榜单与趋势雷达（P0 榜单/库；P1 雷达）
- 当下验证轨：已有现实需求和可执行的验证/切入路径；未来观察轨：新基础设施/制度/行为变化导致的潜在需求。
- 日榜动态数量，重要性排序；不达门槛输出「今日无足够高可信机会」而非填充内容。
- 历史趋势标 `observed`/`forecast`，预测带区间、关键触发条件及修订记录；记录首次发现/最后验证/热度/证据变化。
- **验收**：高热度但无购买行为的项目不能自动进入已验证榜；删除或失效的证据能触发降级。

### FR-10 深度研究与角色化报告（P1）
- 可从榜单、机会详情或自然语言启动；报告结构覆盖 3.2 的全部章节，提供三类角色视角。
- 使用 Markdown 为**唯一权威可编辑报告源**；PDF/Word/PPT 是该快照派生导出。每一份导出附 `report_version`, `as_of`, `evidence_cutoff`, `scoring_version`。
- 支持对证据或结论追问、对比反证、生成验证计划，回答时引用本次研究材料；不能凭空提供最新数据。
- **验收**：导出文档与同版本页面数据一致；过期报告显示需刷新，不自动覆写旧版本。

### FR-11 AI 对话助手（P1）
- 研究范围显式限定到公共情报/当前私有项目，避免跨用户泄露；可追问“为什么高分”“反证是什么”“如果我是一个人做呢”。
- 结构化工具调用受 RBAC + tenant_id + budget_scope 控制；用户问「帮我发信」不代表授权发送。
- 对话引用相同 evidence/claim ID；提示模型表达证据类型与不足，不在追问中改变历史已发布结论而无版本记录。
- **验收**：跨租户越权请求拒绝；敏感对外工具只有审批 token 可调用。

### FR-12 产品孵化工作台（P1 基础；P2 扩展）
- 机会→项目：用户手动转化为私有项目；保留源机会 ID，但所有私有资料默认隔离。
- 状态机：观察→预研究→问题验证→客户/付费验证→MVP 设计→MVP 测试→商业化试点→扩张 / 终止 / 搁置。
- 每阶段都有「继续 / 转向 / 停止」关卡，需记录证据、决策人、理由、下一步、预算消耗。
- 生成访谈提纲、问卷、落地页文案、PRD、MVP 范围、定价试验方案；执行外部测试须用户批准。
- **验收**：未完成的问卷不能被标记成已做访谈；没有真实付款数据不得显示付费转化率。

### FR-13 关注、预警与通知（P1）
- 关注维度：行业、国家、客群、竞品、机会、关键指标阈值。变更事件覆盖竞品新功能/降价、证据变质、需求信号变化、监管事件、市场进入窗口。
- 通道：站内优先，邮件或手机推送按用户授权启用；重大变化去重、合并、静默期和通知预算。
- 每条通知包含发生了什么、证据、变化前后、是否需要动作、可信度；不把实时性当承诺。
- **验收**：同一事件跨三来源只发一次提醒，可退订且遵从用户时区。

### FR-14 管理后台与权限（P0 基础；P2 完整）
- 超管 / 审核员 / 普通用户 / 企业管理员等角色；公共目录与私人研究严格物理/逻辑隔离（RLS + 应用鉴权）。
- 功能：凭据存储（不回显）、连接器开关、预算、研究质量抽样、人工覆核、Skill 发布回滚、通知、审计和运行状态。
- **验收**：管理面板不泄露 API Secret；普通用户无权读取其他用户的项目摘要及日志。

### FR-15 插拔式模型与 Skill（P0 引擎基础；P1 后台）
- 模型由 provider adapter 连接，统一消息、工具调用、结构化输出、成本测量、超时/回退协议。
- Skill 按独立版本发布，有输入输出 schema、prompt_hash、评估集、允许的数据权限和工具权限。
- 关键商机可触发独立模型的反向论证，但模型一致不作为独立市场证据。
- **验收**：更换模型无需改业务表结构；回滚 Skill 版本不会影响历史报告追溯。

### FR-16 成本调度（P0）
- 每个任务赋予 `priority`/`estimated_cost`/`max_cost`/`value_of_information`；先廉价检索和去重，进入高价值层才深度研究。
- 工作流幂等键、请求缓存、批量嵌入、采集 cursor、有效期刷新、成本分摊。
- 预算层级：平台/租户/用户/项目/任务；软阈值提醒、硬阈值停付费调用并降级/排队；关键安全请求例外需审批。
- **验收**：达到硬上限后不继续付费第三方调用；所有模型与采集费用可追溯到任务 ID。

### FR-17 持续校准、反证与否决（P1）
- 历史评分冻结快照，记录用户反馈、实地验证、付费结果和市场变化；回测系统性偏差（如热度偏见、地区偏见）。
- 不把用户不执行直接当负标签；区分信息误判、需求误判、模式误判、执行问题和宏观变化。
- 硬否决：违法/无法取得必要资质、不可绕过的关键限制、明确且可靠的需求不存在证据等；**证据缺失不得作为硬否决**。
- 人审可撤销否决，且必须留下审计。
- **验收**：在相同历史样本上新旧方法对比；红线命中停止推荐、保留档案与再次审核条件。

## 5. 六个端到端核心旅程

**J1 每日自动发现**：许可来源采集→规范化/独立去重→抽取人群-场景-任务→相似聚合→多维分析→竞品和反证→证据门槛→榜单/观察库→事件通知。

**J2 指定行业**：输入「日本养老×居家照护×预算20万」→解析→范围确认（只在必要时）→多信源检索→机会列表→按成本/可信筛选→深挖一项。

**J3 模糊想法验证**：用户说「做一个 AI 宠物陪伴 App」→先拆分「用户要什么/谁付钱/当前替代是什么」→反例检索→输出已知/未知→设计最小验证，不无条件赞美想法。

**J4 无付费数据**：发现大量企业对账抱怨→同类产品定价未知→计量人工耗时（来源与假设单列）→识别预算控制人→寻找现有替代支出→给付费证据 L1/L2（按实际材料）→建议 10 个访谈＋询价/预售测试，仍可评潜力。

**J5 跨市场迁移**：在美国识别需家长签收的学校服务→检索中国相关规则/文化/替代品→本地化重验→生成「国外已验证/中国待验证」标签，不复制海外评分。

**J6 机会孵化**：收藏→创建私有项目→生成假设树→用户批准实验→上传结果→更新评分→推进下一阶段或退出→系统继续跟踪行业和竞争事件。

## 6. 关键异常、空状态与防幻觉

| 状态 | 系统行为 | 禁止行为 |
|---|---|---|
| 某信源无许可/无法抓取 | 明确展示未覆盖平台、可补充的授权方式；调度其他来源 | 暗示覆盖了该平台、规避访问控制 |
| 无直接付费证据 | 输出代理证据/假设/最小测试；状态 `payment_unverified` | 断言「用户愿意买」「已验证商业闭环」 |
| 无可靠竞品收入 | 展示官网定价和商业模式；收入 `unknown` | 编造收入/下载量/份额 |
| 高潜力、低可信 | 进入观察/验证清单，展示不确定性 | 当作 S 级立即投资推荐 |
| 竞争少但无需求 | 进入待验证池或淘汰（需反证） | 把零竞品视作蓝海证明 |
| 高质量源冲突 | 展示分歧、时间、口径、各自可靠性 | 擅自取平均数掩盖冲突 |
| 抓取失效/数据过期 | 停止更新评分相关事实、标记 stale | 以旧内容宣称「最新」 |
| 第三方费用爆增 | 熔断、通知、转低成本检索 | 在超预算后继续运行付费研究 |

## 7. 数据安全、法律与版权原则

1. 所有来源进系统前走许可与用途白名单；遵守 robots/平台规则/API 商业许可、隐私和著作权。*可见网页*不等于*可以批量采集或再分发*。
2. 公开帖子只保留必要的允许使用数据，针对用户标识进行最小化/脱敏；提供来源删除/授权撤销的传播式删除。
3. 用户上传的访谈、内部数据、创意和实验结果默认为 tenant-private；公共、私有检索索引分开；日志不得落盘明文密钥或个人隐私。
4. 不允许以用户原书全文训练模型，除非另有明确授权；本书仅作为该工作流的用户提供参考资料，Skill 使用自主整理的规则与短引用/页码，不公开再分发原书。
5. 任何涉及个人联系、调查邀约、购买/支付/广告、公开发布的行动，需要 scope 与金额/受众/渠道的单独批准。
6. 地区合规、健康/金融/法律行业机会只能给商业情报与风险提示，不自动生成违规营销或无资质实施方案。

## 8. 非功能需求（首轮建议性目标，非已达成指标）

- 数据完整性：同一任务幂等重试不应产生重复 Opportunity；采集留原始指纹与异常原因。
- 页面：普通查询 P95 < 3s（不含实时深度研究）；长任务异步排队＋进度事件，前端不等待任务完成。
- 可观察性：每轮研究含 request_id、job_id、connector_id、skill_version、model_version、spent_cost、trace/span、状态和失败原因。
- 可恢复性：持久化队列、重试退避、死信队列、定期备份和恢复演练。
- 安全：最小权限、RLS、传输和静态加密、审计日志、密钥轮换、保留/删除策略。
- 运营：中英文 i18n、原文保存、无障碍色彩/键盘可访问，移动端基本可用。
- 可迁移：PostgreSQL + 对象存储 + 标准 HTTP API + OCI 容器；避免只有某家云能运行的业务逻辑。

## 9. 首版成功标准（分层、待试点校准）

**技术验收**：连续 14 日任务执行，无授权源采集事件、无超预算执行、无跨租户信息泄露；关键流水线成功率建议 ≥95%，不可用的来源不计入覆盖。

**研究质量验收**：人工审阅至少 30 个多行业多地区研究样本。引用可点击且能支撑其对应 claim；关键事实零编造容忍；假设/事实标记与人工金标准一致率建议 ≥90%；竞品遗漏率与错合并率单独记录。

**真实用户价值验收**：创始人自测→邀请 6–12 位覆盖三类角色的试点用户；记录完成的访谈/立项/否决等决策动作、实际证据价值、用户回访。此处样本与目标**是试点设计建议，不是市场验证结果**。

**停止/转向条件**：3 轮试点仍无法保证可追溯且无幻觉的结论，暂停扩展信源，先修正质量引擎；用户只阅读报告却不采取任何行动，优先调查行动门槛/输出可用性，而不是新增榜单功能。

## 10. 优先级与阶段概述

| 阶段 | 可用价值 | 核心模块 | 本阶段不做 |
|---|---|---|---|

## 11. 依赖、风险、待验证假设

- **头号经营风险：数据许可与可持续获取**。首先做「信源准入目录」，不能以爬虫能否跑通衡量信源可用性。
- **头号研究风险：需求热度替代付款意愿**。必须把现有支出、预算、认知/成交阻力纳入评分。
- **头号算法风险：伪精确打分**。证据少时输出区间/暂不判断，不给满分式假象。
- **头号产品风险：工作台太重**。第一屏先给「一句话结论 + 为什么 + 下一步」，深度细节按需展开。
- **头号开发风险：Coding Agent 反复重构**。API/Schema/测试先行，按文档版本完成任务，有架构变更提案（ADR）。
- **书籍内容风险**：用户提供 MD 有少量文本识别噪声，关键术语以 PDF 版面核对；原书经营观察中的历史数据不可作为 2026 年最新市场事实使用。
