## 用户补充的第 47 项刚性要求（不是替代原 46 项）

**缺乏可直接观测付费数据时继续研究，不否决、不停滞**：查当前替代性支出、真实时间/组织成本、预算链路、询价/试用行为、竞品同类交易（如可核验）；独立输出「商业潜力」「付款证据等级」「关键未知」「最低成本下一步实验」。从不以推测替代真实收款证据。详见 `01 FR-06` 与 `02 §3`。

## 不能擅自替用户确定的开放事项

- **品牌具体名称**：用户只选中英文双品牌，不等于已完成命名。
- **收费与套餐**：用户选择先验证产品价值，不应写固定价格。
- **月运行预算**：先根据真实数据量/模型计费测算。
- **交付截止日期**：以功能阶段和验收为准。
- **全平台接口授权**：尚未取得，必须逐项验证；无法授权时降级处理。
- **每个机会的真实商业结果**：开发前不能假装已完成市场实验。

## 需求变更协议

- 修改本矩阵必须有用户新的明确决定及对应日期。
- 添加新功能须说明是否改变核心价值判断、成本、权限、数据合规和已冻结 API。
- 发生冲突时新增 ADR，并标明原决策号与候选方案，**Coding Agent 不得自己替用户做产品方向变更**。
